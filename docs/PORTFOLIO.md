# Product, research and model publication plan

Use three connected artifacts so a hiring reviewer can understand the work quickly:

1. **OpenMemory GitHub repository:** the working local-first app, tests, architecture/setup notes and a concise [fine-tuning case study](FINE_TUNING_CASE_STUDY.md). Keep API keys, personal memories, runtime environments, adapter/base weights, full learning logs, third-party datasets and large diagnostic snapshots out of this repo. A model identifier/inference interface is sufficient; weights can be obtained separately once a reviewed release exists.
2. **Separate research GitHub repository:** a curated reproducible trainer/evaluator, dependency versions, dataset construction and provenance, comparison results, failure examples and a readable learning walkthrough. The complete local research archive is the source material, not the public package. Some scripts/logs currently depend on local absolute paths and need a portability pass. Start with original fictional examples; publish third-party text only after checking redistribution terms and providing attribution. A separate dataset release is optional and is not implied by a model release.
3. **Hugging Face model repository, later:** a reviewed adapter/inference package with exact base/revision/configuration, installation example, model license and a model card describing training data, evaluation and limitations. The app will link to that versioned release rather than duplicate weights. No Hugging Face upload or public research repo has been created yet.

Hugging Face's [model-card guidance](https://huggingface.co/docs/hub/model-cards) calls for intended use, limitations, training parameters/data and evaluation results. Its [dataset-card guidance](https://huggingface.co/docs/hub/datasets-cards) covers dataset contents/context and metadata. Prepare separate accurate cards; older local drafts for the MiniLM experiment do not describe the current Qwen MLX adapter.

Next concrete research work: select the reviewed730 version as an experimental candidate, create a small portable export, audit source/license provenance, replace absolute machine paths with configuration, reproduce inference from the exported directory, and decide whether additional untouched evaluation is required before release. Choose repository names/account and release licenses before publishing that package. Do not attach a new license to third-party text merely because it was publicly accessible.

For applications, lead with the working app and the case study. Describe the project as AI-assisted fine-tuning/evaluation experience; report development metrics with their denominators and limitations. The regression/rejection story and actual product failure cases are useful evidence of engineering judgment. You do not need to publish every log to demonstrate that work.
